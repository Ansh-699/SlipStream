# Check: S10 — Ops, secrets, supply chain, build and deploy

**Run:** `audit-e2e` · **Issue draft:** `docs/runs/audit-e2e/issues/10-s10.md`
**Spec pointer:** `docs/spec/audit-e2e.md` §2 (calibration), §3 (severity), §4
(document and record format), §7 `### S10` (this slice).

## Purpose

S10's deliverable is a *document*, not a diff, so this check grades the document.
Every RUN item below is a single command that exits 0 or non-zero on its own — no
reader judgement is involved anywhere. Together they are designed so that a findings
file produced by skimming, or by inventing citations, fails: the `evidence` item
opens every path cited and counts its lines, the `cleared` item requires all 11
threat-class ids to be accounted for with a resolving citation, and the `proof` item
requires every CONFIRMED record to carry pasted output or a scratch reproduction.

What this check deliberately does **not** grade: whether a finding is *correct*, and
whether its severity is *right*. Those are the closing review's call. This check
establishes only that the auditor did the work in a form that can be reviewed.

## Fix contract

A failure here means the findings document is malformed or incomplete — it does not
mean the audit reached a wrong conclusion. The file to fix is always
`docs/audit/audit-e2e/s10.md` and never anything else. Each RUN item prints the exact
records or class ids that failed, so the repair is targeted:

- `evidence` failing → a citation is wrong; open the file and re-read it.
- `cleared` failing → a threat class was not accounted for; go look at it, then
  write what you found. Do not paper it over with a bullet that cites nothing.
- `proof` failing → a record is marked CONFIRMED that is really SUSPECTED. Downgrade
  it and state the settlement criteria; that is the honest repair, not fabricating
  output.
- `nodiff` failing → this run modified source. Revert it. The run shape is audit-only.

If a RUN item is wrong *about the spec*, that is a ruling for the orchestrator, not a
rewrite of this file: `docs/checks/**` is read-only after the freeze commit.

## Graded items

The grammar is normative from `skills/architect/check-runner.ps1`; see
`skills/architect/dispatch.md` `## Check-runner dispatch`. All commands run from the
repository root.

The shared grader is `docs/checks/audit-e2e/validate-findings.py`, frozen with this
file. It reads its threat-class list from `docs/checks/audit-e2e/classes.tsv`, prints
`PASS <slice> <mode>` or `FAIL <slice> <mode>` plus one line per defect, and exits 0
on pass / 1 on fail. One mode per item, so each item asserts exactly one fact.

- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 exists` -> exit:0 match:"PASS S10 exists"
  — the findings file is at the exact expected path and is not a stub.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 headings` -> exit:0 match:"PASS S10 headings"
  — all four required section headings are present.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 calibration` -> exit:0 match:"PASS S10 calibration"
  — the spec section 2 calibration sentence is reproduced verbatim.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 records` -> exit:0 match:"PASS S10 records"
  — every `###` heading parses as `<SID>-NN` / `<SID>-XNN` and ids are unique.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 status` -> exit:0 match:"PASS S10 status"
  — every record carries exactly one CONFIRMED or SUSPECTED.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 severity` -> exit:0 match:"PASS S10 severity"
  — every record carries exactly one severity from the four-level scale.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 tag` -> exit:0 match:"PASS S10 tag"
  — every P0/P1 carries exactly one [reachable-now]/[mainnet-only]; no P2/P3 carries one.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 class` -> exit:0 match:"PASS S10 class"
  — every record's Class is a real class id owned by this slice.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 evidence` -> exit:0 match:"PASS S10 evidence"
  — every record cites at least one path:line, and EVERY citation resolves to a real file at a line that exists.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 proof` -> exit:0 match:"PASS S10 proof"
  — every record has a Proof block; every CONFIRMED one has pasted output or a repro/ reference.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 impact` -> exit:0 match:"PASS S10 impact"
  — every record has What is wrong / Blast radius / Suggested remediation.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 routed` -> exit:0 match:"PASS S10 routed"
  — every cross-slice note sits under its heading and names its target slice.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 cleared` -> exit:0 match:"PASS S10 cleared"
  — the negative-results section accounts for EVERY threat class with a resolving citation.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 minfindings` -> exit:0 match:"PASS S10 minfindings"
  — a slice that owns established known state filed at least one own finding.
- RUN: `python3 docs/checks/audit-e2e/validate-findings.py S10 nodiff` -> exit:0 match:"PASS S10 nodiff"
  — this run modified no product, keeper, frontend, test, or doc file.

Two items guard the check itself rather than the auditor, and must also pass:

- RUN: `test -f docs/checks/audit-e2e/classes.tsv` -> exit:0
  — the normative class enumeration the grader reads is present.
- RUN: `test "$(awk -F'\t' '$1=="S10"' docs/checks/audit-e2e/classes.tsv | wc -l)" -eq 11` -> exit:0
  — S10 still declares exactly 11 threat classes; a silent edit to the TSV would
    otherwise weaken every `cleared` grading in this file.

## Not graded — read by the closing review only

- Are the CONFIRMED findings actually true, and is each severity defensible against
  the mainnet threat model in spec §3?
- Does the `## Cleared` section show real work, or a bullet per id that technically
  resolves but demonstrates nothing? The check can only prove a citation exists.
- Did the slice route what it should have routed, rather than filing outside its own
  file set or staying silent about a defect it saw?
- S10 owns established known state (K2 - the operator key holding three capabilities at once). The check enforces
  `>= 1` finding; only the review can say whether it is the *right* finding.

**Duration hint (informative, not a ceiling):** the graded items are seconds. The
audit that produces the document is roughly one sitting.
