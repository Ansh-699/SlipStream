# Frozen check — R3 `lossless-fill-ring`

**Run:** `remediate` · **Slice:** `lossless-fill-ring` · **Issue:** `docs/runs/remediate/issues/03-lossless-fill-ring.md`
**Spec:** `docs/spec/remediate.md` — Decision 5

## Purpose

`push_fill_event` overwrites the oldest entry at capacity and returns `Ok(())`, destroying fills that
money already moved for; `mirror_fills` then jumps the hole its cursor never checks for. This slice
makes the producer refuse, the consumer detect the gap, and — critically — the consumer **drain**, so
that refusing does not wedge the market permanently.

## Fix contract

- Item **1 or 2** failing is an environment problem, not a builder defect — see R1's contract.
- A failure of **3 or 4** means the producer still destroys fills. Fix `push_fill_event` in
  `programs/slipstream/src/state/order_book.rs` — never the test.
- A failure of **5** means the mirror still steps over a gap. Fix
  `programs/slipstream/src/instructions/mirror_fills.rs`.
- **A failure of 6 is the most serious outcome in this slice.** It means the drain runs only over
  what the call appended, so a ring full of already-mirrored fills never clears, `place_order` stays
  halted, and the market is wedged with no operator recovery. The live ER ring is in exactly that
  state right now (`head == tail == 3229`, `count == 4096`, oldest surviving 40094). Fix the drain to
  cover every entry whose `sequence <= last_mirrored_sequence`, independent of appends, and move it
  **before** the `appended == 0` early return. Do not weaken the test.
- A failure of **7** means the gap check has no virgin-log exemption. The keeper rotates epochs
  routinely and a fresh FillLog re-mirrors from sequence 0 by design
  (`keepers/src/fill-log-keeper.ts:171-175`), so an unconditional check breaks every rotation
  forever. Fix `mirror_fills.rs`.
- A failure of **8** means `OrderBookHeader` grew, which would misread the live 612 KB book. Fix
  `order_book.rs`; do not touch `tests/unit/src/test_state.rs`.
- A failure of **9** means the client still passes the OrderBook read-only, so the drain cannot land
  on chain no matter what the program does. Fix `client/src/instructions.ts`.
- A failure of **11** is a lint regression introduced by this slice.

Duration hint: item 1 is a full SBF rebuild, roughly 1–3 minutes cold.

## What each item asserts, and why it can fail

1. The SBF artifact exists.
2. **No regression.** All 123 pre-existing tests still pass.
3. All four ring tests exist and pass. The `match` is mandatory: a filter matching zero tests exits 0.
   The builder writes the fourth (`..._succeeds_on_virgin_log_after_rotation`); the other three are
   drafted at `docs/runs/remediate/draft-tests/test_fill_ring_lossless.rs`.
4. **The producer attack is blocked.** A push onto a full ring returns an error, `fill_event_head`
   and `fill_event_count` do not move, and the oldest stored `FillEvent` is byte-identical. Verified
   to fail against the unmodified program: *"push_fill_event returned Ok on a full ring — the oldest
   unmirrored fill was destroyed"*.
5. **The consumer attack is blocked.** A ring whose oldest surviving sequence is `last_mirrored + 5`
   is refused and the cursor does not advance. Verified to fail against the unmodified program with
   `Success`.
6. **The wedge is closed.** A full ring whose every entry is already mirrored must drain to
   `fill_event_count == 0` on a call that appends nothing. Verified to fail against the unmodified
   program with `Failure(Custom(285))` — that is `FillQueueEmpty`, ordinal 29, returned by
   `mirror_fills.rs:144-150` before any drain could run. Without this item a builder can satisfy
   items 4 and 5 and still ship a permanently halted market.
7. **Epoch rotation still works.** A virgin log (`count == 0`, `last_mirrored_sequence == 0`) against
   a wrapped ring must succeed rather than trip the gap check.
8. The two existing `mirror_fills` regression tests still pass, unmodified.
9. `OrderBookHeader::LEN == 48` and the whole layout module, 32 tests, unmodified.
10. **Specifically `orderBook` in `createMirrorFillsInstruction` is writable**, scoped by `awk` to
    that function's body so it cannot be satisfied by an unrelated writable meta elsewhere in the
    file, and so it does not break when line numbers shift. This is the item that catches "program
    drains, client never lets it". Verified against the current tree: the `true` form exits 1 today,
    the `false` form exits 0.
11. No new lint.

## Not graded by the runner — for the closing review

- Matching **will** halt on the first post-upgrade run against the live book. That is intended
  (intake ruling 3) and belongs in the deploy runbook, not in a fix.
- The 33,146 already-destroyed fills are not recovered by this or any slice.
- `mirror_fills` stays permissionless. The drain is bounded by the log's own
  `last_mirrored_sequence`, so a caller can only discard entries the FillLog already holds, and the
  drain is ER-local state never committed to L1. If the builder gates the instruction instead, that
  is a scope change and needs a ruling.
