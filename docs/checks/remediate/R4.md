# Frozen check — R4 `settlement-reader`

**Run:** `remediate` · **Slice:** `settlement-reader` · **Blocked by:** R1 · **Issue:** `docs/runs/remediate/issues/04-settlement-reader.md`
**Spec:** `docs/spec/remediate.md` — Decisions 3, 5, 6

## Purpose

The settlement cursor is a high-water mark, so a fill absent from the batch settles **zero** times —
33,146 sequences on the live market, 75 % of every fill ever matched. The same reader applies
ER-authored `count` and `filled_margin` with no bound of any kind. This slice makes the cursor
contiguous, bounds every ER-authored field it reads, and lands the settlement half of R1's ledger
invariant.

## Fix contract

- Item **1 or 2** failing is an environment problem, not a builder defect — see R1's contract.
- A failure of **4** means the cursor still jumps a gap. Fix the loop in
  `programs/slipstream/src/instructions/settle_from_log.rs` — never the test.
- A failure of **5** means `count` is still unbounded and `S4-07`'s 819× replay is open. Fix the
  validation block.
- A failure of **6** means `filled_margin` is still applied verbatim and `S4-06` is open.
- A failure of **7** means the contiguous-prefix rule is **defeated**, not merely incomplete: the
  cursor is a `u32` and a `u64` sequence above `u32::MAX` truncates on write and moves it backwards.
  Bound the input; do **not** widen the cursor — `Market::_padding2` is only 6 bytes and widening it
  changes nothing that helps.
- A failure of **8** means R1's ledger is not being debited at settlement, which leaves the ceiling
  loose by each user's realised losses. Fix the debit, `saturating_sub`, one per leg.
- A failure of **9** means the orphan `break` was converted to a skip. That is a regression of a
  prior fix, not a simplification: advancing past an orphan lets any permissionless caller skip the
  whole queue by passing no remaining accounts. Restore the `break`.
- A failure of **10** is a lint regression introduced by this slice.

Duration hint: item 1 is a full SBF rebuild, roughly 1–3 minutes cold.

## What each item asserts, and why it can fail

1. The SBF artifact exists.
2. **No regression.** All 123 pre-existing tests still pass. Settlement is the densest accounting in
   the program; this is the item that catches a cursor change that broke fee scaling.
3. All five settlement tests exist and pass. The `match` is mandatory: a filter matching zero tests
   exits 0.
4. **`S4-01` is closed.** A log holding sequences {1, 2, 5} with `last_settled = 0` leaves the cursor
   at **2**. Verified to fail against the unmodified program at `left: 5, right: 2` — today it lands
   on 5 and orphans 3 and 4 forever.
5. **`S4-07` is closed.** `capacity = 2, count = 100` is rejected and mints no `Position.collateral`.
   Verified to fail against the unmodified program with `Success`.
6. **`S4-06` is closed.** A `filled_margin` 1000× the leverage bound for the fill's own quantity and
   price is rejected. Verified to fail against the unmodified program with `Success`.
7. **The contiguity rule is not trivially defeated.** A fill with `sequence = 4_294_967_307` against
   `last_settled = 10` must be rejected. Verified to fail against the unmodified program, which
   accepts it and truncates the cursor to 11 — moving it **backwards**. Without this item items 4–6
   can all pass while the whole cursor design is bypassable.
8. **R1's invariant is exact, not approximate.** One honest fill lowers `credit_outstanding` by the
   `filled_margin` applied to each leg. Verified to fail against the unmodified program at
   `left: 1000000000, right: 990000000` — the field is dead today.
9. The two existing `settle_trades` regression tests still pass, unmodified. They pin the reduce-to-flat
   collateral release and the scaled maker rebate, both of which live in the loop being edited.
10. The ledger debit is actually present in the settlement source, at least twice — one per leg — so
    item 8 cannot be satisfied by a coincidence in the fixture. Scoped to one file, so no self-match
    against this check and no collision with the repo name.
11. No new lint.
