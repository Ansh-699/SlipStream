# Frozen check — R1 `credit-ceiling`

**Run:** `remediate` · **Slice:** `credit-ceiling` (anchor) · **Issue:** `docs/runs/remediate/issues/01-credit-ceiling.md`
**Spec:** `docs/spec/remediate.md` — Decisions 1, 2, 3, 4, 4b

## Purpose

L1 must gain its own record of how much of a user's collateral is parked inside trading credits, on
an account the ER provably cannot write, and `withdraw_trading_credit` must be bounded by it. This
is the anchor: every other slice is arranged around it, and R4 consumes the field it publishes.

## Fix contract

- Any failure of item **1 or 2** is an environment problem, not a builder defect: the SBF artifact is
  gitignored, so a fresh worktree has no `target/deploy/slipstream.so` and 38 Mollusk tests fail with
  "Program file not found". Run item 1 first, always.
- A failure of **3, 4 or 5** means the ceiling is wrong. Fix
  `programs/slipstream/src/instructions/withdraw_trading_credit.rs`,
  `fund_trading_credit.rs`, or `seed_credit_ledger.rs` — never the test.
- A failure of **6** means the rename moved bytes or changed a size. Fix
  `programs/slipstream/src/state/user_account.rs`. `UserAccount::LEN` must stay 56.
- A failure of **7** means an off-chain decoder was left reading a field that no longer exists, or was
  moved off byte 48. Fix the four decode sites, not the struct.
- A failure of **8** means a **new ownership-transfer mechanism** entered the program, which
  invalidates Decision 1's proof that the ER cannot author a `UserAccount` byte. Do not adjust the
  count to match. Stop and escalate: the anchor slice's premise no longer holds.
- A failure of **9** is a lint regression introduced by this slice. Four clippy errors pre-exist at
  the freeze (`lib.rs:11` ×3 `unexpected_cfgs`, `order_slot.rs:53` `too_many_arguments`) and are
  suppressed by the flags in the command; anything else is this slice's.

Duration hint: item 1 is a full SBF rebuild, roughly 1–3 minutes cold. Item 2 is under a minute.

## What each item asserts, and why it can fail

1. The SBF artifact exists. Everything Mollusk-shaped depends on it.
2. **No regression.** All 123 pre-existing tests still pass — 25 in `programs/slipstream`, 98 in
   `tests/unit`. This is the item that catches a fix that closes one hole by opening another.
3. All three new ceiling tests exist and pass. The `match` is mandatory: a `cargo test` filter that
   matches **zero** tests still exits 0, so without it a deleted or renamed test would grade green.
4. **The specific attack is blocked.** An ER-committed `credit.credit = 1_000_000_000_000` against a
   user whose ledger records 50 USDC must not move an atom. Verified to fail against the unmodified
   program with `Success` and a moved `free_collateral`.
5. **The fix is not over-tight.** A full honest fund-then-withdraw round trip still succeeds and
   returns the ledger to zero. Verified to fail against the unmodified program at
   `left: 0, right: 100000000` — the ledger is never raised today.
6. `UserAccount::LEN == 56`, `TradingCredit::LEN == 96`, `Position::LEN == 96`,
   `OrderBookHeader::LEN == 48`, `GlobalState::LEN == 104` — the whole layout module, 32 tests,
   passing unmodified. Note for the reader: these assertions **already existed** before this run and
   did **not** catch `S1-01`. A deliberate `LEN` change updates the assertion alongside itself. The
   real `S1-01` check is R2's reachability test.
7. The rename reached all four off-chain decoders. Scoped to the four named files, so it cannot
   self-match this check file or collide with the repo's own name.
8. **Decision 1's enumeration still holds.** Three `Assign`-to-delegation sites, six direct
   owner-slot writes (all to the System program), twelve `CreateAccount` CPIs (all
   `owner: program_id`). A fourth mechanism, or a fourth delegation target, breaks the proof that the
   ER cannot write `UserAccount.credit_outstanding` — and therefore breaks the whole slice.
9. No new lint. The four pre-existing errors are suppressed by name; the bare
   `-D warnings` form exits 101 at the freeze and would fail every builder.

## Not graded by the runner — for the closing review

- `seed_credit_ledger` writes `min(credit.credit, amount)`, never `credit.credit` verbatim. 46 live
  credits will be seeded with it, 22 of which currently carry ER-authored values above 10^12 raw.
- The ledger is exact only once R4 lands. R1 alone bounds extraction at each user's cumulative
  realised losses, which is a large improvement but is not conservation.
- Decision 4b's second repair lives in R2 (`close_trading_credit` refusing a non-empty credit). If R2
  does not land, gate 2 can permanently lock a user's `free_collateral`.
