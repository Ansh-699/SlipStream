# Frozen check — R2 `legacy-credit-recovery`

**Run:** `remediate` · **Slice:** `legacy-credit-recovery` · **Issue:** `docs/runs/remediate/issues/02-legacy-credit-recovery.md`
**Spec:** `docs/spec/remediate.md` — Decision 4, Decision 4b

## Purpose

Four live 56-byte `TradingCredit` accounts holding **13,313.24 USDC** are refused by every
instruction that could return the money, because all 18 load sites reject
`data.len() < TradingCredit::LEN`. This slice makes exactly one instruction length-tolerant, returns
the balance to `free_collateral`, and stops `close_trading_credit` from silently destroying a modern
credit's balance.

## Fix contract

- Item **1 or 2** failing is an environment problem, not a builder defect — see R1's contract.
- A failure of **3 or 4** means the recovery path is wrong. Fix
  `programs/slipstream/src/instructions/close_trading_credit.rs` or the fixed-offset reader in
  `programs/slipstream/src/state/trading_credit.rs` — never the test.
- A failure of **5** means the recovery branch became reachable with a modern 96-byte account, which
  turns it into a bypass of R1's ceiling **and** re-opens the silent fund destruction. Fix the length
  discrimination, not the assertion.
- A failure of **6** means `TradingCredit::LEN` moved off 96. The version byte goes in `_padding`,
  which is inside `LEN`. Fix `trading_credit.rs`; do not touch `tests/unit/src/test_state.rs`.
- A failure of **7** is a lint regression introduced by this slice.

Duration hint: item 1 is a full SBF rebuild, roughly 1–3 minutes cold.

## What each item asserts, and why it can fail

1. The SBF artifact exists.
2. **No regression.** All 123 pre-existing tests still pass. This is the item that catches a
   length-tolerant reader that loosened a guard somewhere else.
3. Both recovery tests exist and pass. The `match` is mandatory: a filter matching zero tests exits 0.
4. **`S1-01` is actually closed.** A 56-byte credit holding 13,163,240,000 atoms — the real live
   value — closes and the balance lands in `UserAccount.free_collateral`. Verified to fail against
   the unmodified program with `Failure(InvalidAccountData)`, which is the 96-byte guard refusing.
   **This is the check that would have caught `S1-01`, not the `LEN` assertion.** A `LEN` assertion
   cannot catch a deliberate `LEN` change; a reachability test can.
5. **R2 is not a hole in R1.** Closing a modern 96-byte credit that still holds `credit > 0` is
   refused and moves no funds. Verified to fail against the unmodified program with `Success` — today
   that call destroys the balance, and after R1 it would also strand `credit_outstanding` and lock
   the owner's entire `free_collateral` behind `withdraw_collateral`'s gate 2.
6. The whole layout module, 32 tests, unmodified.
7. `TradingCredit::LEN == 96` is still asserted in the layout test — pins that the assertion was not
   deleted to make item 6 pass.
8. The legacy length constant exists in the state module, so the discrimination is a named constant
   rather than a magic 56 buried in the instruction.
9. No new lint.

## Not graded by the runner — for the closing review

- The 12 delegated legacy credits (**36,470.00 USDC**, re-read read-only 2026-08-22) are **not**
  recovered and cannot be: the program owns none of their bytes and has no L1 undelegation path. That
  is `S5-02`, P1, out of scope. The job report must say so plainly rather than implying full recovery.
- The layout-version byte lives in ER-owned `_padding`. That is acceptable only because it dispatches
  a read and never authorises a payout.
