# Frozen check — R5 `pending-fills-symmetry`

**Run:** `remediate` · **Slice:** `pending-fills-symmetry` · **Issue:** `docs/runs/remediate/issues/05-pending-fills-symmetry.md`
**Spec:** `docs/spec/remediate.md` — slice R5

## Purpose

`pending_fills` is bumped once per distinct user and decremented once per (fill, side), with no
reset path anywhere. It gates both `withdraw_collateral` and `close_user_account`, so on the live
deployment **13 of 45** accounts holding **438,643.10 USDC** can neither withdraw nor close. This
slice restores the symmetry on the producing side and adds the authority-gated clear that unblocks
the already-stuck accounts.

## Fix contract

- Item **1 or 2** failing is an environment problem, not a builder defect — see R1's contract.
- A failure of **4** means `reset_pending_fills` is wrong. Fix
  `programs/slipstream/src/instructions/reset_pending_fills.rs` — never the test. If the failure is
  the stranger half, the authority gate is missing or reads the wrong field; if it is the authority
  half, the instruction is not dispatched or does not clear the counter.
- A failure of **5** means the existing `record_pending_fill` authentication regression broke. That
  instruction is R7's file — if R5 touched it, that is a boundary violation, not a fix.
- A failure of **6** means the keeper still dedupes to distinct users, so the bump and the decrement
  still count different units and the defect is only papered over by the reset instruction.
- A failure of **7** is a lint regression introduced by this slice.

Duration hint: item 1 is a full SBF rebuild, roughly 1–3 minutes cold.

## What each item asserts, and why it can fail

1. The SBF artifact exists.
2. **No regression.** All 123 pre-existing tests still pass.
3. The reset test exists and passes. The `match` is mandatory: a filter matching zero tests exits 0.
4. **The specific attack is blocked and the specific unlock works.** A stranger calling
   `reset_pending_fills` is refused and `pending_fills` is unchanged; the authority's call sets it to
   0 and moves no balance. Verified to fail against the unmodified program with
   `Failure(InvalidInstructionData)` — the instruction does not exist today.
5. `record_pending_fill`'s existing authentication regression still passes, unmodified. That
   instruction is deliberately *not* changed by this slice.
6. The new instruction file exists on disk. Filesystem `test -f`, not `git grep`: a builder's new
   file in an unstaged worktree is invisible to `git grep`.
7. The dispatch constant is present. Pre-landed at freeze, so this item catches a builder who
   removed or renamed it.
8. **The symmetry half actually landed.** `keepers/src/fill-log-keeper.ts` shows exactly one changed
   file in the working diff. This is a weak item by construction and is called out as such: the
   invariant now lives partly in an off-chain script, which is strictly weaker than an on-chain rule.
   The closing review must read the diff, not trust this item.
9. No new lint.

## Not graded by the runner — for the closing review

- **Named ceiling.** The bump/decrement symmetry is enforced by a TypeScript keeper, not by the
  program. The durable fix is to gate withdrawal on a specific unsettled sequence rather than a
  free-running counter. That is recorded as follow-up and is deliberately not done here.
- `reset_pending_fills` is a standing authority-gated clear of a withdrawal gate. The argument that
  this grants no new capability is the same one intake ruling 2 makes for `seed_credit_ledger`: the
  holder of `GlobalState.authority` is also the upgrade authority and can already replace the
  program. If the key ceremony in `S10-01` ever happens, both instructions should be revisited.
- The fills that would legitimately decrement the 13 stuck accounts are among the 33,146 destroyed by
  `S4-01`. Nothing recovers them; the reset is the only path.
